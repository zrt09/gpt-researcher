## 1. 网页入口（最终版本：只用原网页）

`python main.py` 启动后打开 `http://127.0.0.1:8000/`，报告类型选 “Adaptive - 自适应研究” 即可。
轮次、子任务、指标和决策显示在日志区；最终报告在整轮结束后一次性出现。

> **历史记录**：v1.1 曾提供 `/adaptive-ui` 独立调试页；最终交付版已移除该页面
> （删除 `backend/server/adaptive_ui.py`，并同步移除 `app.py` 中的 import 与路由挂载）。
> 本文不再提供其启动方式和接口说明。

## 2. 报告结构：改造前 vs 改造后

### 改造前（你看到的那份）

```
# The 2026 Nobel Prize in Physics: ...
## Executive Summary
## The Laureate: Francis Halzen
### Biographical Background
### Key Institutional Affiliations
## The Scientific Breakthrough Explained in Plain Terms
### What Are Neutrinos?
...
## Significance in Physics
## Announcement, Institution, and Ceremony Details
## Prize Money and Allocation
## Reactions and Expert Commentary
## Context Within Recent Nobel Physics Trends
## Assessment and Opinion          ← 观点性章节，噪音
## Conclusion
## 研究质量自检                     ← 中文附录混在英文报告里

```

问题：章节未编号、层级不固定、混入"观点/花絮"类章节、附录语言与正文不一致、标题重复。

### 改造后（同题复测）

```
# 2026年诺贝尔物理学奖得主及其主要贡献

### 公布时间与奖项归属

### 南极冰下两千五百米…
## 4. 高能中微子的探测原理与技术路径
### 探测原理与传感器布局
### 从光信号到中微子事件
## 5. 冰立方中微子发现的意义
## 6. 学界与媒体对获奖成果的解读

## 附录：研究质量自检          ← 语言跟随正文

```

差异：**单一 H1、章节编号连续、摘要/结论/参考文献固定、章节数与计划任务对齐、附录语言跟随正文**。

## 3. 结构是怎么被强制出来的

新增 `gpt_researcher/adaptive/writer_v2.py`，把"一次让模型写整篇"改成流水线：

```
1) 大纲：根据问题 + 证据标题，产出 4~7 个不重叠章节（JSON）
2) 分节：每节一次调用，只带该节相关证据（最多 6 条），并行 3 路
3) 摘要 / 结论：基于各节摘要单独生成
4) 装配：单一 H1 + 编号章节 + 确定性参考文献（来自证据，不靠模型编）
5) 净化：删除/改指未收集的 URL；规范化标题层级与空行
```

配套工具 `textutil.py`：

| 函数 | 作用 |
| --- | --- |
| `detect_language` | 判定中/英，决定正文与附录语言 |
| `normalize_markdown` | 保证只有一个 H1，去掉空标题，压缩空行 |
| `number_sections` | 给正文章节编号（摘要/结论/参考文献/附录不编号） |
| `sanitize_citations` | 未收集的 URL → 按标题改指到证据，或降级为纯文本 |

降级链：结构化写作失败 → 一次性写作 → 证据摘要（保证永远有报告，且状态标 `partial`）。

## 4. 这次挖出的根因（原来的"乱"不只是文风问题）

| # | 根因 | 后果 | 修复 |
| --- | --- | --- | --- |
| 1 | 完整性指标只认 `Introduction/引言` | 报告写 `Executive Summary` 被判"缺引言"→ 覆盖再高也不达标 → 套用失败附录 | 新增 executive summary/summary/overview/abstract/摘要/概述 等别名 |
| 2 | 规划用英文写子任务目标（哪怕问题是中文） | 中文报告无法与英文目标匹配，覆盖度只有 0.125 | 规划提示词强制"与问题同语言" |
| 3 | 中文短标题 vs 长目标：整串相似度接近 0 | 覆盖度长期偏低 | 改为"区分性 3-gram 命中 + URL 归属 + 词面归属"三路判定 |
| 4 | 句子切分在 URL 的 `?` 处断开 | 带查询串的引用被截断 → 引用可回溯率 0.2~0.5 | 只在"句末 + 空白/CJK"处切分 |
| 5 | 清洗句子时删掉 `_` 与链接 URL | `..._120678874` 变 `...120678874`，引用全部对不上 | URL 从原始句子提取，不再经过清洗 |
| 6 | 模型写裸 URL（无 markdown 链接） | 净化器漏掉，报告引用未收集页面 | 净化器增加"裸 URL"通道 |
| 7 | 已完成任务的覆盖缺口被当成"要补研究" | 计划越滚越大（5→8），覆盖度分母变大 | 改为"写作侧缺口 → 重写报告" |

## 5. 门槛与计划规模的调整

| 配置 | 旧值 | 新值 | 原因 |
| --- | --- | --- | --- |
| `ADAPTIVE_MIN_COVERAGE` | 0.80 | **0.70** | 词面归属是保守下界；0.80 在 5~6 任务上近乎不可达 |
| `ADAPTIVE_MAX_TASKS` | 8 | **6** | 报告章节数（≤7）不可能一一覆盖 8 个任务 |
| `ADAPTIVE_PLAN_TASKS` | — | **5** | 新增：初始计划只排 5 个，补研任务占用剩余名额 |

## 7. 仍存在的限制

1. **来源时效性恒为 `None`**：证据里没有发布日期，指标只展示不参与门槛。
2. **`full` 评估模式未默认开启**：结论级证据支持率（LLM 判定）需要 `eval_mode=full`，会多 5~8 次调用。
3. **只保留原网页入口**：早期 `/adaptive-ui` 调试页已下线；老的 Web 前端（Next.js）仍需 npm 安装，未改动。
4. **覆盖度仍是启发式**：中文可用了，但极端表述（同义改写）仍可能漏判，属于已知误差。
5. **PDF 导出依赖 WeasyPrint**：Windows 上缺 GTK 库会失败（只影响 PDF，不影响 md/docx/网页）。
