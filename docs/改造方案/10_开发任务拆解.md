# 10 开发任务拆解

> 阶段 3 交付物。依据 05~09 号设计文档，把设计拆成 28 个可独立验收的任务。
> 每个任务都必须是"能单独跑测试、能单独提交"的最小单元。

---

## 0. 分批与顺序调整说明

设计文档里建议的顺序是：状态 → 规划 → 评估 → 反思 → 预算 → 整合。**代码审计后我调整了一处**：

| 调整 | 原计划 | 实际计划 | 原因 |
| --- | --- | --- | --- |
| `Planner.revise()` 的位置 | 第二批（规划阶段） | **第四批（T18）** | `revise()` 的输入是 `evaluation.deficits`，第三批才有 `EvaluationResult` 的真实结构。提前实现只能写空壳，等评估落地时必须返工。 |

其余顺序不变。每批结束都能得到一个**可运行**的中间态（不是"写完才第一次跑"）。

## 2. 任务详情

### T01 新增 `ADAPTIVE_*` 配置项

- **目标**：让所有自适应参数可通过 `.env` / 配置文件覆盖，且默认关闭。
- **涉及文件**：`gpt_researcher/config/variables/base.py`、`default.py`
- **新增**：`ADAPTIVE_ENABLED`、`ADAPTIVE_MAX_ROUNDS`、`ADAPTIVE_MAX_LLM_CALLS`、`ADAPTIVE_MAX_TOKENS`、`ADAPTIVE_MAX_SECONDS`、`ADAPTIVE_MAX_COST_USD`、`ADAPTIVE_MAX_TASKS`、`ADAPTIVE_MAX_TASKS_PER_ROUND`、`ADAPTIVE_CONCURRENCY`、`ADAPTIVE_EVAL_MODE`、`ADAPTIVE_MIN_COVERAGE`、`ADAPTIVE_MIN_SUPPORT_RATE`、`ADAPTIVE_MIN_CITATION_MATCH`、`ADAPTIVE_MIN_COMPLETENESS`、`ADAPTIVE_MAX_CONFLICT`、`ADAPTIVE_NO_PROGRESS_ROUNDS`、`ADAPTIVE_VALIDITY_SAMPLE`、`ADAPTIVE_FRESHNESS_MONTHS`、`ADAPTIVE_STATE_DIR`
- **前置**：无
- **测试**：`tests/test_adaptive_config.py` —— `Config()` 无环境变量时取默认值；设 `ADAPTIVE_MAX_ROUNDS=5` 时属性为 `5`；类型转换正确（int/float/bool）
- **验收**：原有配置项一个不改；`ADAPTIVE_ENABLED` 默认 `False`
- **可能问题**：`base.py` 的类型注解必须与 `convert_env_value` 支持的转换保持一致（尤其 `bool` 与 `float`）

### T02 `state.py` 数据模型与校验

- **目标**：落地 07 号文档的全部数据结构。
- **涉及文件**：新增 `gpt_researcher/adaptive/__init__.py`、`state.py`
- **新增类**：`ResearchState`、`SubTask`、`TaskStatus`、`TaskOrigin`、`Evidence`、`Claim`、`SupportLevel`、`EvaluationResult`、`MetricResult`、`Deficit`、`RoundRecord`、`PlanSnapshot`、`BudgetState`、`ReportVersion`、`RunStatus`、`StopReason`
- **前置**：T01
- **测试**：`tests/test_adaptive_state.py` —— 序列化往返、7 条不变量、证据裁剪上限、id 唯一性
- **验收**：`validate()` 对非法状态抛 `ValueError`；`to_dict()` 可 `json.dumps`
- **可能问题**：`set` 不能直接 JSON 序列化（`visited_urls` 需转 list）；`Optional[EvaluationResult]` 的嵌套反序列化

### T03 状态持久化

- **目标**：每轮把状态落盘，崩溃后至少可读。
- **涉及文件**：新增 `gpt_researcher/adaptive/storage.py`
- **新增函数**：`save_state(state, dir) -> Path`、`load_state(path) -> ResearchState`、`save_report_version(text, round_no, dir) -> ReportVersion`、`_atomic_write(path, content)`
- **前置**：T02
- **测试**：临时目录往返；写入中途抛异常不留下半文件；损坏 JSON 报可读错误
- **验收**：同一 run 重复写不炸；文件名/路径符合 07 号文档约定
- **可能问题**：Windows 下 `os.replace` 对已存在文件的行为（需先 `os.remove`？实测 `os.replace` 可直接覆盖）

### T04 `budget.py` + LLM 用量钩子

- **目标**：四类资源计数与熔断；每次 LLM 调用自动上报。
- **涉及文件**：新增 `gpt_researcher/adaptive/budget.py`；修改 `gpt_researcher/utils/llm.py`
- **新增**：`BudgetLimits`、`BudgetController`、`Usage`
- **修改**：`create_chat_completion(..., usage_sink=None)`，调用成功后上报 `input_tokens/output_tokens/cost`
- **前置**：T01、T02
- **测试**：`tests/test_adaptive_budget.py`（边界/首次触顶原因/假时钟）+ `tests/test_llm_usage_sink.py`（传 sink 被调用一次；不传时行为不变）
- **验收**：`usage_sink=None` 时 `tests/test_costs.py` 等既有用例全绿；不新增网络请求
- **可能问题**：`provider.last_usage_metadata` 可能为 `{}`（DeepSeek 路径），需回退到 `calculate_llm_cost` 的估算并标记 `estimated=True`

### T05 批次一单测 + 回归

- **目标**：跑 `pytest tests/ -q`，确认 883 passed 不变（除既有 2 个失败）。
- **前置**：T01~T04
- **验收**：新增用例全绿；既有基线不变；提交前 `git status` 干净
- **可能问题**：`adaptive/` 被 pytest 误收集（无测试）；不影响

### T06 规划提示词

- **目标**：新增 `generate_plan_prompt(query, max_tasks)` 与 `generate_gap_query_prompt(deficit)`。
- **涉及文件**：`gpt_researcher/prompts.py`
- **前置**：无
- **测试**：`tests/test_adaptive_prompts.py` —— 包含 query 与 max_tasks；输出为合法字符串；不破坏既有 prompt 方法
- **验收**：不修改任何既有 prompt 方法的签名/行为
- **可能问题**：中文 query 的 JSON 指令需要明确"只输出 JSON"

### T07 `Planner.initial_plan()`

- **目标**：LLM → 3~6 个 `SubTask`（含 `goal`），带降级。
- **涉及文件**：新增 `gpt_researcher/adaptive/planner.py`
- **前置**：T02、T06
- **测试**：注入固定响应（正常/畸形/空/超量）→ 任务数与字段正确；畸形走降级计划（原问题 + 2 视角）
- **验收**：任何输入都返回 ≥1 个任务（除非 LLM 完全不可用 → 抛明确异常）
- **可能问题**：模型返回带解释文字 → 需 `json_repair` + 提取首个 JSON 块

### T08 任务去重与合并

- **目标**：新任务与已有任务语义重复时不新增，把 `goal` 合并。
- **涉及文件**：`planner.py`
- **前置**：T07
- **测试**：同义 query 判重（"RAG 的局限"/"RAG 有哪些局限"）；阈值边界；合并后 goal 非空
- **验收**：去重后任务数 ≤ 上限；不误杀"同主题不同角度"（用两个真实样例标定阈值）
- **可能问题**：`rapidfuzz` 对中文的 `token_set_ratio` 效果与英文差异较大，阈值需实测（可能需按语言给不同阈值）

### T09 `Claim` 抽取（结构化）

- **目标**：从 markdown 报告抽出结论句 + 所属章节 + 引用 URL。
- **涉及文件**：新增 `gpt_researcher/adaptive/claims.py`
- **前置**：T02
- **测试**：固定报告 fixture → claim 数、section 正确、`cited_urls` 正确；无引用句的处理；表格/代码块不误抽
- **验收**：纯规则实现，**不调 LLM**（light 模式要求零成本）
- **可能问题**：中文句子切分（用 `。！？` + 换行）；列表项是否算 claim（规则：含引用或含数字/年份的列表项算）

### T10 零成本指标

- **目标**：`coverage / citation_match_url / completeness / freshness` 四个纯函数。
- **涉及文件**：新增 `gpt_researcher/adaptive/metrics.py`
- **前置**：T02、T09
- **测试**：`tests/test_adaptive_metrics.py` —— 每个指标的正常/空集/全空三种 fixture；分母为 0 时 `value=None`
- **验收**：不发起任何网络/LLM 调用；`citation` 的 URL 归一化有用例
- **可能问题**：中文标题与 goal 的词面匹配召回低 → 覆盖度偏低（已知误差，08 号文档已注明）

### T11 URL 有效性检查

- **目标**：抽样检查引用 URL 是否可访问。
- **涉及文件**：`metrics.py`
- **前置**：T10
- **测试**：注入 fake sampler → 2xx/404/429/超时四类统计；去重；限并发
- **验收**：默认抽样 20 条；401/403/429 计为 `blocked` 而非 `invalid`
- **可能问题**：HEAD 被拒 → 回落 GET；被反爬拦截会拉低指标（已用 `blocked` 区分）

### T12 `Evaluator`（light）+ `QualityGate`

- **目标**：组装指标、产出 `EvaluationResult`、判定 `passed`。
- **涉及文件**：新增 `gpt_researcher/adaptive/evaluator.py`
- **前置**：T10、T11
- **测试**：`tests/test_adaptive_evaluator_light.py` —— 达标/不达标/指标缺失三种；缺陷生成正确
- **验收**：light 模式 LLM 调用数 = 0；指标异常不影响其它指标
- **可能问题**：`passed` 在必需指标缺失时的保守取值（必须为 False）

### T13 `Evaluator`（full）

- **目标**：证据支持率、引用语义匹配、冲突识别。
- **涉及文件**：`evaluator.py`、`metrics.py`、`prompts.py`（新增 judge prompt）
- **前置**：T12
- **测试**：注入 fake judge → 批处理次数、截断标记 `sampled`、`evidence_id` 越界判 `unchecked`
- **验收**：LLM 调用数 ≤ ⌈claims/10⌉ + 4；预算不足时降级 light 而非报错
- **可能问题**：judge 返回非 JSON；同一模型自评偏差（用 `evidence_id` 集合校验兜底）

### T14 执行适配器 + `artifact_sink`

- **目标**：一个子任务 → 一个 `GPTResearcher` 实例 → `Evidence[]`。
- **涉及文件**：新增 `gpt_researcher/adaptive/executor.py`；修改 `gpt_researcher/agent.py`（加 `artifact_sink`/`usage_sink` 透传）、`gpt_researcher/skills/researcher.py`（两处回调）
- **前置**：T02、T04
- **测试**：monkeypatch `GPTResearcher` 为 Fake → 证据条数/字段/去重；异常 → FAILED
- **验收**：`artifact_sink=None` 时原路径零行为变化（回归测试）
- **可能问题**：`_process_sub_query` 与 `_scrape_data_by_urls` 两个回调点会重复触发，需按 `(sub_query, url)` 去重

### T15 `researcher.py` 失败语义改造

- **目标**：研究失败不再静默返回 `[]`/`""`，让上层可判定。
- **涉及文件**：`gpt_researcher/skills/researcher.py`
- **前置**：T14
- **测试**：monkeypatch 检索器抛异常 → `ResearchOutcome.status == FAILED` 且 `error` 非空；返回类型向后兼容
- **验收**：既有 883 个用例全绿（这是**风险最高**的一次改动，必须单独提交）
- **可能问题**：某些调用方依赖"空字符串表示没内容"，改成对象会破坏 → 采用"新增 `last_outcome` 属性 + 返回值不变"的兼容方案

### T16 `ReflectionEngine` 决策表

- **目标**：09 号文档的 11 级优先级 + 12 行决策表。
- **涉及文件**：新增 `gpt_researcher/adaptive/reflection.py`
- **前置**：T12
- **测试**：12 行逐行用例
- **验收**：纯函数、无异常路径、兜底 `NO_PROGRESS`
- **可能问题**：条件优先级写反（用表驱动实现，避免 if 嵌套）

### T17 `Planner.revise()`

- **目标**：`deficits` → 新子任务。
- **涉及文件**：`planner.py`
- **前置**：T08、T16
- **测试**：5 类缺陷各生成 1 条任务；超上限截断；与已有任务去重
- **验收**：生成的任务都带可判定的 `goal`
- **可能问题**：`suggested_query` 为空时的兜底（用 claim 原文构造检索式）

## 4. 每批的"可运行中间态"

| 批次结束 | 系统能做什么 | 不会做什么 |
| --- | --- | --- |
| 一 | 配置可读、状态可建可存、预算可计数 | 不产生任何研究行为 |
| 二 | 能把问题拆成带目标的任务 | 不执行任务 |
| 三 | 能给一份报告打分 | 不驱动循环 |
