# 03 核心模块复用分析（模块复用清单）

> 依据：01/02 号文档的代码实测结论
> 分类口径：**A 完全不需要修改** / **B 只需增加接口（扩展示性改动）** / **C 需要修改内部逻辑** / **D 需要新增模块**
> 原则：优先复用原项目已有的搜索、抓取、压缩、写作、成本、事件能力，避免重复实现

---

## 1. 结论速览

| 分类 | 模块数 | 代表模块 |
| --- | --- | --- |
| A 完全不需要修改 | 大量 | 检索器、抓取器、LLM Provider、Markdown 处理、日志、URL 安全 |
| B 只加接口 | 6 | `create_chat_completion`、`GPTResearcher`、`Config`、`ResearchObserver`、`ResearchConductor.conduct_research`、`PromptFamily` |
| C 需改内部逻辑 | 3 | `skills/researcher.py`（失败语义/结构化工件）、`actions/report_generation.py`（报告与评估的衔接）、`skills/deep_research.py`（外部预算/停止原因） |
| D 需要新增 | 6~7 | Planner / Evaluator / Reflection(Decision) / Budget / State / Loop Orchestrator + 报告附带评估结果 |

> 关键判断：**功能 A~D 的主体应当落在"新增编排层 + 新增状态对象"上，底层检索/抓取/写作几乎不用动。** 这也是"改造量最小、能真正落地"的前提。

---

## 2. 模块复用清单（逐项）

### 2.1 完全不需要修改（A）

| 原有模块 | 当前作用 | 是否复用 | 是否修改 | 修改理由 |
| --- | --- | --- | --- | --- |
| `retrievers/`（24 个后端 + 插件） | 把 query 变成 URL/摘要 | ✅ 全量复用 | ❌ | 搜索能力已完备；新增规划只改变"发什么 query"，不改检索器 |
| `scraper/`（BS/Playwright/Firecrawl/PDF…） | URL → 正文 | ✅ 全量复用 | ❌ | 抓取质量与并发控制已实现 |
| `llm_provider/`（GenericLLMProvider） | 统一各厂商 LLM | ✅ 全量复用 | ❌ | 评估/规划只是新的调用方 |
| `context/compression.py`、`context/select.py`、`context/lexical.py` | 长文压缩、相似度筛选、降级 | ✅ 复用 | ❌ | 评估器可直接复用 `select_context` 做"证据定位" |
| `actions/markdown_processing.py` | 标题/章节/TOC/References | ✅ 复用 | ❌ | 评估报告章节可复用 `extract_sections` |
| `utils/costs.py` | token→美元估算 | ✅ 复用 | ❌ | 预算需要的是 **token**，但价目表/usage 解析可复用 |
| `utils/url_security.py`、`utils/logger.py`、`logging_config.py` | URL 安全、日志 | ✅ 复用 | ❌ | — |

| `backend/server/*`（除必要的字段透传） | Web 服务、日志落盘、报告文件 | ✅ 复用 | ⚠️ 极小 | 若要展示"评估结果"需在返回体里加字段（见 B） |
| `tests/` 既有 181 个用例 | 回归保护 | ✅ 必须复用 | ❌ | 改造不得破坏它们 |

### 2.2 只需要增加接口（B）

| 原有模块 | 当前作用 | 是否复用 | 是否修改 | 修改理由 |
| --- | --- | --- | --- | --- |

| `config/config.py` + `variables/` | 配置中心 | ✅ | ⚠️ 只加配置项 | 新增 `ADAPTIVE_MAX_ROUNDS`、`BUDGET_TOKEN`、`QUALITY_TARGET` 等，不改解析逻辑 |

| `backend/server/*` 的 `run_agent` / `server_utils` | 分派与落盘 | ✅ | ⚠️ 新增字段透传 | 把"评估摘要/停止原因"带到前端 |

### 2.3 需要修改内部逻辑（C）

| 原有模块 | 当前作用 | 是否复用 | 是否修改 | 修改理由 |
| --- | --- | --- | --- | --- |
| `skills/researcher.py:430-432, 678-687` | 异常时**静默返回 `[]` / `""`** | ✅ 复用框架 | ✅ 必须改 | 这是"伪造完成"的根源：研究失败后仍会写报告。需改为返回带 `status/error` 的结果对象（或至少让上层可感知失败） |
| `skills/researcher.py` 的 context 产出 | 字符串拼接 | ✅ | ✅ 改 | 评估需要"结论↔证据"可定位，需在拼接时保留 `{url,title,chunk,snippet}` 结构（新增结构化工件，不破坏原字符串输出） |
| `skills/deep_research.py:551-571` | 递归下钻，停止条件只靠 depth | ✅ 复用递归范式 | ✅ 改 | 接入外部预算与"信息缺口驱动"，并把停止原因写回状态；不改递归结构本身 |
| `skills/writer.py:49 write_report` | 单次生成整篇 | ✅ 复用 | ✅ 改（新增参数） | 支持"带上一轮评估意见的定向修订"，而不只是重写 |

### 2.4 需要新增（D）

| 新模块（建议位置） | 职责 | 为什么不能复用 |
| --- | --- | --- |
| `gpt_researcher/adaptive/state.py` | 研究状态对象（计划、子任务、结论-证据、轮次、成本、停止原因） | 原项目只有实例属性 + 多 Agent 的 TypedDict，两者都不适合标准模式 |
| `gpt_researcher/adaptive/planner.py` | 拆解 + 动态增删改子任务 + 去重 | `plan_research_outline` 只产 `list[str]`，无状态、无 ID、不可修订 |
| `gpt_researcher/adaptive/evaluator.py` | 量化质量评估（覆盖度/证据支持/引用匹配/来源有效性/时效性/冲突/完整性） | `SourceCurator` 只评来源；`fact_checker` 是二值文本复核；`evals/quality_eval` 是离线评测，不是在线环节 |
| `gpt_researcher/adaptive/reflection.py` | 由评估结果生成"补研/重规划/重写/结束"决策 | 无对应物 |
| `gpt_researcher/adaptive/budget.py` | 轮次/调用数/token/时长预算与熔断 | 只有美元成本记录，无上限 |
| `gpt_researcher/adaptive/orchestrator.py` | 外层循环：规划→执行→评估→反思→（终止） | 标准模式无循环；多 Agent 的图不能直接驱动标准模式 |
| `gpt_researcher/adaptive/reporting.py`（可选） | 生成"评估结果 + 未解决问题"附录 | 现有报告不含质量自检 |

## 4. 明确"不复用 / 不改造"的部分（及理由）

| 候选 | 决定 | 理由 |
| --- | --- | --- |
| 用 LangGraph 重写标准研究流程 | ❌ 不做 | 标准流程是线性 async 流水线，加循环只需外层 `while` + 状态对象；重写图会带来巨大回归风险，违背"增量开发" |
| `multi_agents/`（LangGraph 工作流） | ✅ 保留原样，作为对照 | 它是"多 Agent 协作"的另一条产品线，与本项目"单 Agent 自适应研究"定位不同 |
| `multi_agents/ag2/` | ❌ 不动 | 旧版 AG2 实现，已非主路径 |
| `deep_agents/` | ❌ 不复用 | 依赖外部 `deepagents` 包（当前环境**未安装**），且是"总编+子 Agent"范式，与目标不同 |
| 新增数据库/向量库 | ❌ 不新增 | 状态只需单任务内存 + 可选 JSON 落盘；引入 DB 属于过度设计 |
| 新增第三方依赖 | ❌ 默认不新增 | 评估/规划/预算均可用现有 LLM + 标准库完成 |
| 修改 `tests/` 既有用例来"让测试通过" | ❌ 禁止 | 验收要求明确禁止 |

## 6. 复用带来的改造量估算（相对量，供阶段 3 细化）

| 工作 | 强度 | 说明 |
| --- | --- | --- |
| 新增状态对象 + 事件 | 中 | 纯新增，无回归风险 |
| 新增规划器 | 中 | 复用 `create_chat_completion` 与既有 prompt 风格 |
| 新增评估器 | **高** | 需要"结论—证据"结构化中间层 + 多项指标，且要控制 LLM 调用成本 |
| 新增反思/决策 | 中 | 规则 + 少量 LLM 调用 |
| 新增预算 | 低 | 钩子 + 计数器 |
| 改失败语义 | 中 | 触碰 `researcher.py` 热点路径，必须配回归测试 |
| 外层编排 | 中 | 新增类，不改原 `conduct_research` 默认行为 |

> 结论：**改造量主要集中在"新增"上，唯一的高风险改动是 `skills/researcher.py` 的失败语义与结构化工件**，必须放在最后一批并配合测试。
