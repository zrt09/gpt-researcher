# 09 动态决策与终止机制

> 任务书 2.5 要求明确回答：何时继续研究 / 何时重新规划 / 何时补充证据 / 何时重新生成报告 / 何时可以结束 / 预算耗尽但质量不达标怎么办
> 本文件给出**决策表 + 伪代码 + 优先级 + 无进展检测 + 防伪造完成契约**

---

## 1. 决策的唯一输入

每轮结束（第 3.5 步）只有三个输入：

```python
ev:     EvaluationResult     # 7 项分项指标 + 缺陷列表 + passed
state:  ResearchState        # 计划、证据、历史轮次
budget: BudgetController     # 四类资源余额 + 首个触顶原因
```

**决策输出唯一**：`Decision{action, reason, new_tasks, rewrite_notes}`，`action ∈ {supplement, replan, rewrite, finish, abort}`。

---

## 2. 决策优先级（从高到低，短路求值）

```
P0  预算耗尽                        → finish（stop_reason = 首个触顶原因）
P1  质量达标                        → finish（QUALITY_MET）
P2  评估整体不可用（必需指标全 None） → abort
P3  连续 N 轮无进展                  → finish（NO_PROGRESS）
P4  存在 missing_coverage 缺陷        → supplement
P5  证据支持率不足                   → supplement（找更强证据）
P6  引用不可解析/失效                → supplement（换来源）
P7  存在冲突                        → supplement（交叉验证）
P8  结构不完整                      → rewrite
P9  证据充足但表述超出证据            → rewrite（收紧表述）
P10 计划整体错位（≥2 任务同时失效）    → replan
P11 兜底                            → finish（NO_PROGRESS）
```

> **顺序即策略**：先谈"能不能继续"（预算），再谈"要不要继续"（质量/进展），最后才谈"怎么继续"（补研/重写/重规划）。

---

## 3. 六个问题的直接回答

### Q1：什么情况下需要**继续研究**？

满足全部条件时：

1. 预算未触顶（`budget.exhaust_reason() is None`）；
2. 质量未达标（`ev.passed == False`）；
3. 有明确的、可执行的缺陷（`ev.deficits` 非空，且至少一条能映射为新任务或重写指令）；
4. 未触发无进展检测。

### Q2：什么情况下需要**重新规划**（replan）？

- 同一轮评估中，**≥2 个任务的 `covered` 判定失败**，且这些任务来自首轮拆解（`origin=INITIAL`）；
- 或连续两轮补充研究后，**同一批缺陷反复出现**（说明不是"缺证据"，而是"问题拆错了"）。

触发后：保留已完成任务与证据，`plan_version += 1`，新增/替换未完成任务，`PlanSnapshot` 记录 diff。

### Q3：什么情况下需要**补充证据**（supplement）？

| 缺陷类型 | 补研策略 |
| --- | --- |
| `missing_coverage(task_id)` | 复用原查询 + 加入"限定词"（时间/来源类型），生成 1~2 条新检索式 |
| `weak_evidence(claim_id)` | 抽取 claim 的关键实体 → 生成"精确检索式"（引号短语） |
| `broken_citation(url)` | 用 claim 原文 + 站点名重建检索式，替换失效来源 |
| `conflict(claim_pair)` | 生成"交叉验证"检索式（如 `A vs B 数据 2025`） |
| `stale(source)` | 生成"最新/2025/2026"限定检索式 |

补研任务数受 `ADAPTIVE_MAX_TASKS` 与单轮上限约束；每条补研任务都必须带 `goal`（可验收），否则不允许执行。

### Q4：什么情况下需要**重新生成报告**（rewrite，不新增研究）？

- 结构不完整（缺结论/缺章节）；
- 存在 `unsupported` 结论**且**证据已充分（即"证据里有，但报告没引用/表述过头"）；
- 上一轮 `rewrite_notes` 未被执行（文本未变化且指标无提升）。

重写时把 `rewrite_notes` 作为"修订指令"传给 `writer.write_report(revision_notes=...)`，**只重写受影响章节**（v1 实现整篇重写 + 指令，v2 再做章节级）。

### Q5：什么情况下可以**结束研究**？

| 结束方式 | 条件 | `status` |
| --- | --- | --- |
| 质量达标 | `QualityGate.passed == True` | `COMPLETED` |
| 预算耗尽 | 任一上限触顶 | `PARTIAL`（若已有报告） / `FAILED`（无报告） |
| 无进展 | 连续 `ADAPTIVE_NO_PROGRESS_ROUNDS` 轮指标不升且无新证据 | `PARTIAL` |
| 不可恢复 | 规划/评估/执行全面失败 | `FAILED` |

**结束 ≠ 成功**。`stop_reason` 必须写清，报告必须带附录（见第 6 节）。

### Q6：**达到预算上限但质量不达标**，怎么处理？

这是最关键的一条，按以下固定流程：

```
1. 立刻停止新的研究任务（不再发起搜索/抓取/LLM 调用）
2. 用当前已有证据生成"最终报告"（不再追求达标）
3. 强制附加「未完成事项」章节，内容必须包含：
   a. 触顶原因（哪一项预算、用到多少、上限多少）
   b. 未达标的指标及具体数值（例：coverage=0.62 < 0.80）
   c. 未解决的子任务清单（task id + goal + 缺什么）
   d. 当前报告的已知薄弱点（unsupported 结论逐条列出）
   e. 建议的下一步（人工补充哪些来源 / 放宽哪个门槛 / 增加预算重跑）
4. status = PARTIAL，绝不写 COMPLETED
5. 若连报告都生成失败 → status = FAILED，输出失败原因与已完成部分
```

> 这条流程直接对应任务书"当无法完成任务时，明确报告未解决的问题，不得伪造完成状态"。

## 4. 主循环伪代码

```python
async def run(self, on_round=None) -> AdaptiveResult:
    state = ResearchState(run_id=..., query=self.query, budget=BudgetState(...))
    budget = BudgetController(state.budget, clock=self.clock)

    plan = await self.planner.initial_plan(self.query)      # 失败 → status=FAILED, 直接返回
    state.plan = plan

    while True:
        ok, reason = budget.can_start_round()
        if not ok:
            state.stop_reason = reason
            break

        round_no = state.budget.rounds + 1
        emit("adaptive_round_started", round=round_no)

        # 3.2 执行本轮任务（并发受限）
        tasks = state.open_tasks()[: self.max_tasks_per_round]
        results = await gather_limited(tasks, self.executor.run_task, limit=self.concurrency)
        for r in results:
            state.apply(r)                       # evidence/task status/visited_urls

        # 3.3 报告
        draft = await self.writer.write(state, revision_notes=self.pending_notes)
        state.report = draft
        state.report_versions.append(save_version(draft, round_no))

        # 3.4 评估
        ev = await self.evaluator.evaluate(state, draft, mode=self.eval_mode)
        state.latest_evaluation = ev

        record = RoundRecord(round=round_no, evaluation=ev, tokens..., cost...)
        state.rounds.append(record)

        # 3.5 终止判定（先硬后软）
        stop = budget.exhaust_reason() or self.gate.check(ev)
        if stop:
            state.stop_reason = stop
            record.decision = "finish"; break

        # 3.6 反思决策
        d = self.reflection.decide(ev, state, budget)
        record.decision, record.decision_reason = d.action.value, d.reason

        if d.action is Action.ABORT:
            state.stop_reason = StopReason.ERROR; break
        if d.action is Action.FINISH:
            state.stop_reason = StopReason.NO_PROGRESS; break
        if d.action is Action.REPLAN:
            state.apply_plan(await self.planner.revise(state, ev), round_no)
        if d.action is Action.SUPPLEMENT:
            state.apply_plan(d.new_tasks, round_no)
        if d.action is Action.REWRITE:
            self.pending_notes = d.rewrite_notes

        # 3.7 无进展检测
        if self.no_progress(ev, state, window=self.no_progress_rounds):
            state.stop_reason = StopReason.NO_PROGRESS; break

        state.budget.rounds += 1
        on_round and on_round(record)
        save_state(state)                        # 每轮落盘

    state.status = finalize_status(state)
    report = append_evaluation_appendix(state)
    save_state(state); save_report(report)
    return AdaptiveResult(report, state.latest_evaluation, state, state.status, state.stop_reason)
```

## 5. 无进展检测（防死循环的核心）

```python
def no_progress(ev, state, window=2) -> bool:
    recent = state.rounds[-window:]
    if len(recent) < window: return False
    # 条件 1：最近 window 轮没有新增证据
    no_new_evidence = all(r.new_evidence == 0 for r in recent)
    # 条件 2：必需指标无一提升（提升阈值 0.02，避免浮点抖动）
    key = ("coverage", "citation_match_url", "completeness")
    flat = all(
        (cur := ev.metrics.get(k)) and (prev := recent[i].evaluation.metrics.get(k))
        and (cur.value is None or prev.value is None or cur.value - prev.value < 0.02)
        for i in range(len(recent))
        for k in key
    )
    # 条件 3：待办任务已空（无事可做）
    nothing_todo = not state.open_tasks()
    return (no_new_evidence and flat) or nothing_todo
```

**三道保险**（任意两道即可防死循环）：

1. 轮次上限 `ADAPTIVE_MAX_ROUNDS`（硬）；
2. 无进展检测（软，通常先触发）；
3. 任务数上限 + 去重（结构性，防止"不断生成相似子任务"）。

## 6. "不得伪造完成"的机器可检契约

| 检查点 | 规则 | 由谁保证 |
| --- | --- | --- |
| `status=COMPLETED` | 必须 `latest_evaluation.passed == True` 且 `stop_reason == QUALITY_MET` | `state.validate()` |
| `status=PARTIAL` | 必须有 `open_questions` 非空，且报告附录含 5 项（触顶原因/未达标指标/未解决任务/薄弱点/建议） | `report.append_evaluation_appendix()` |
| `status=FAILED` | 必须有 `stop_reason ∈ {ERROR, PLANNER_EXHAUSTED}` | orchestrator |
| 任何状态 | 报告不得包含"研究已完成"之类断言，除非 `status=COMPLETED` | 附录模板固定措辞 |
| 评估缺失 | `latest_evaluation is None` ⇒ `status` 不得为 `COMPLETED` | `finalize_status()` |

> 这 5 条在阶段 6 集成测试里必须有对应用例（fixture 构造"预算耗尽但质量不达标"）。

## 7. 状态机

```
        ┌──────────┐
        │ PLANNING │ 首轮拆解失败
        └────┬─────┘ ──────────────► FAILED
             │ plan ok
        ┌────▼─────┐
        │EXECUTING │◄──────────────┐
        └────┬─────┘               │ supplement / replan
             │ 本轮任务完成          │
        ┌────▼─────┐               │
        │EVALUATING│───────────────┘
        └────┬─────┘
             │ passed / budget / no_progress / abort
        ┌────▼─────┐
        │ FINALIZING│──► COMPLETED / PARTIAL / FAILED
        └──────────┘
```

实现上不需要显式状态机类：`status` 字段 + 循环结构即可，`RoundRecord.decision` 记录轨迹。

## 8. 边界与异常处理

| 场景 | 处理 |
| --- | --- |
| 首轮规划返回 0 任务 | `PLANNER_EXHAUSTED` → `FAILED`（不进入循环） |
| 某轮所有任务失败 | 记录；若连续 2 轮全失败 → `ERROR` → `FAILED` |
| 评估全指标 `None` | `abort`（P2） |
| 报告生成抛异常 | 用上一版报告作为最终稿；若没有 → `FAILED` |
| 预算在轮中被撞线 | 当前任务允许跑完（避免半截证据），下一轮不再启动 |
| 时间上限 | 每轮开始检查；**不**中断进行中的调用（简化实现，代价是可能超时几十秒） |
| LLM 持续失败 | `create_chat_completion` 内部重试 10 次后用尽 → 该任务 `FAILED` |
| 重复缺陷 2 轮不变 | 视为"补研无效" → `replan`；再 2 轮 → `NO_PROGRESS` 结束 |

## 10. 与预算的关系（数值示例）

基线成本：**$0.0111 / 次研究**（实测，见 00 号文档）。设：

- `MAX_ROUNDS=3`，`MAX_LLM_CALLS=120`，`MAX_TOKENS=300k`，`MAX_COST=0.10`，`MAX_SECONDS=600`；
- 每轮约 15~25 次 LLM 调用、1.5~3 万 token；
- 3 轮 ≈ 60 次调用 / 8 万 token / $0.03~0.05。

→ 预算应能容纳 3 轮，但不足以容纳 5 轮；若第 3 轮仍未达标，按 Q6 流程输出 `PARTIAL`。

**调参建议**：先按 `MAX_ROUNDS=3, MAX_COST=0.15` 跑 10 个查询，统计实际触顶比例，再决定是否放宽。
