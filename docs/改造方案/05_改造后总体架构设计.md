# 05 改造后总体架构设计

> 阶段 2 交付物（设计，不含实现）
> 前置：01~04 号文档的代码审计结论
> 设计约束：不改原版默认行为、不引入新依赖、不重写为标准流程之外的框架（含 LangGraph）

---

## 1. 设计目标与原则

| 目标 | 落地手段 |
| --- | --- |
| 保留原版研究能力 | `GPTResearcher` 的 `conduct_research()/write_report()` 默认路径**零改动** |
| 支持动态研究 | 新增外层编排 `AdaptiveResearcher`，以"轮次"驱动"规划→执行→评估→反思" |
| 支持质量评估 | 新增"证据/结论"结构化中间层 + 可分项计算的指标 |
| 支持预算与终止 | 单一裁决点 `BudgetController` + 统一 LLM 计数钩子 |
| 可对照 | 同一套代码两种入口：原版 `GPTResearcher` vs `AdaptiveResearcher` |
| 可测试 | 每个新模块纯函数/可注入依赖，不依赖真实 LLM 即可单测 |

**三条硬规则**

1. **默认关闭**：`ADAPTIVE_ENABLED=false`，不显式启用时行为与原版完全一致。
2. **单向依赖**：`adaptive/` 可以 import 原包，原包**不得** import `adaptive/`（除一个可选入口）。
3. **状态唯一**：新增 `ResearchState` 是唯一真相，`GPTResearcher` 的实例属性在每轮结束时同步，不允许双写。

## 4. 完整执行流程

```
AdaptiveResearcher.run(query)
  ├─ 1. 初始化
  │     state = ResearchState(query, budget=BudgetController(limits))
  │     若原版上下文未提供 → 复用原版"选 Agent + 首轮检索"作为探索性上下文（可选，节省一轮）
  │
  ├─ 2. 规划（round=1）
  │     plan = Planner.initial_plan(query)         # 3~6 个子任务，带 goal
  │     state.plan = plan; state.plan_version = 1
  │
  ├─ 3. 轮次循环
  │  while True:
  │     r = state.round+1
  │     emit("adaptive_round_started", round=r)
  │     ├─ 3.1 预算前置检查  Budget.precheck("round")  → 不足则 break(停因=预算)
  │     ├─ 3.2 执行本轮待办任务（并发上限可配）
  │     │      for t in open_tasks[:max_per_round]:
  │     │          result = ResearchExecutor.run_task(t, shared_visited_urls)
  │     │          state.evidence += result.evidence; t.status = result.status
  │     ├─ 3.3 生成/更新报告草稿
  │     │      draft = Writer.write(evidence, plan, revision_notes)
  │     │      state.report_versions.append(draft)
  │     ├─ 3.4 评估
  │     │      ev = Evaluator.evaluate(state, draft, mode=eval_mode)
  │     │      state.rounds.append(RoundRecord(...))
  │     ├─ 3.5 终止判定（先硬后软）
  │     │      stop = Budget.exhaust_reason() or QualityGate.check(ev)
  │     │      if stop: break
  │     ├─ 3.6 反思决策
  │     │      d = Reflection.decide(ev, state, budget)
  │     │      if d.action == finish: break
  │     │      if d.action == replan: plan = Planner.revise(state, ev); plan_version += 1
  │     │      if d.action == supplement/rewrite: 按 d 执行
  │     └─ 3.7 无进展检测（连续 N 轮无新增证据/指标不升 → 停止）
  │
  ├─ 4. 收尾
  │     若 status == partial/failed：生成"未解决问题 + 缺口清单"附录（强制）
  │     落盘 outputs/adaptive/<run_id>/state.json + report_v{n}.md
  └─ 返回 AdaptiveResult(report, evaluation, state, stop_reason, status)
```

## 5. 关键设计决策与理由

### D1：不引入 LangGraph 重写标准流程

- **理由**：标准流程是线性 async 流水线（01 号文档第 10 节），加循环只需"外层 while + 状态对象"；LangGraph 会引入图编译、checkpoint、thread_id 等概念，与"单任务短流程"不匹配，且会把 181 个既有测试依赖的调用路径整体换掉。
- **代价**：得不到图级 checkpoint 与可视化。可接受——状态落盘 JSON 已能满足"过程可回看"。
- **例外**：`multi_agents/` 保持原样，作为"多 Agent 协作"对照，不并入。

### D2：状态用 `dataclass` 而非 pydantic 模型

- **理由**：pydantic 已是依赖，但状态需要频繁 `asdict`/JSON、字段多为容器，dataclass 更轻、无校验开销；校验放在 Planner/Evaluator 的输入边界。
- **代价**：无自动校验，靠 `__post_init__` 与单元测试兜底。

### D3：一个子任务 = 一个 `GPTResearcher` 实例

- **理由**：这样能**完整复用**检索、抓取、压缩、失败重试；若自己拼 `get_search_results + browse_urls`，等于复制 `ResearchConductor` 的逻辑（重复实现风险 R1）。
- **代价**：每个子任务都有一次"选 Agent"的 LLM 调用。**优化**：子任务实例传入 `agent/role`（父级已选定），跳过 `choose_agent`。
- **共享**：`visited_urls` 在父子实例间共享（原代码已支持：`agent.py:166`、`researcher.py:132-135` 注释明确说明）。

### D4：证据结构化在适配层完成，不侵入压缩器

- **理由**：`ContextCompressor` 是热点路径，改它有回归风险。改为在 `ResearchConductor._scrape_data_by_urls` 返回后调用 `artifact_sink`，把 `scraped_content`（含 `url/title/raw_content`）与压缩后的 `web_context` 一起交给适配层切分 Evidence。
- **代价**：Evidence 的"片段"是压缩器挑出的块，不是全文；这是可接受的（评估只需要"该结论附近有来源支撑"）。

### D5：预算双层检查

- **理由**：LLM 计数只能在 `create_chat_completion` 做（唯一收口）；但"这一轮要不要开始"必须在编排层判断，否则会为半轮任务付费。
- **规则**：`Budget.precheck()` 为廉价前置（软判断），`usage_sink` 为权威计数（硬事实）；两者冲突时以 `usage_sink` 为准并立即标记 `exhausted`。

### D6：评估分"轻/全"两档

- **light（默认）**：只跑零成本/近零成本指标（覆盖度、引用 URL 有效性抽样、结论—证据的确定性匹配）。
- **full**：额外跑 LLM 判定的"证据支持率 / 冲突识别"。
- **理由**：每轮全量 LLM 评估会让 token 翻 3~5 倍（04 号文档风险表首项），默认必须便宜。

### D7：终止裁决只在一处

- `Budget.exhaust_reason()` 管"资源用尽"，`QualityGate.check()` 管"质量达标"，二者都在编排层第 3.5 步调用；`Reflection` **只给建议、不做终止**。
- **理由**：避免 deep 递归、multi_agents revision、新循环三套终止逻辑打架（R6）。

### D8：原版可独立运行

- 新增入口 `AdaptiveResearcher`，`GPTResearcher` 不动默认行为；`ADAPTIVE_ENABLED=false` 时 CLI/后端仍走原路径。
- **对照实验**：同一仓库、同一配置、同一查询，分别跑 `cli.py`（原版）与 `cli.py --adaptive`（改造版）。

## 7. 配置项（新增，全部有默认值，默认不改变原行为）

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `ADAPTIVE_ENABLED` | `false` | 是否启用新入口 |
| `ADAPTIVE_MAX_ROUNDS` | `3` | 最大轮次 |
| `ADAPTIVE_MAX_LLM_CALLS` | `120` | 最大模型调用次数 |
| `ADAPTIVE_MAX_TOKENS` | `300000` | 输入+输出 token 上限 |
| `ADAPTIVE_MAX_SECONDS` | `900` | 墙钟时间上限 |
| `ADAPTIVE_MAX_COST_USD` | `1.0` | 美元上限（复用现有估算） |
| `ADAPTIVE_MAX_TASKS` | `8` | 子任务总数上限 |
| `ADAPTIVE_MAX_TASKS_PER_ROUND` | `4` | 单轮执行任务数 |
| `ADAPTIVE_EVAL_MODE` | `light` | `light` / `full` |
| `ADAPTIVE_MIN_COVERAGE` | `0.80` | 覆盖度门槛 |
| `ADAPTIVE_MIN_SUPPORT_RATE` | `0.85` | 证据支持率门槛（full 模式） |
| `ADAPTIVE_MIN_CITATION_MATCH` | `0.80` | 引用匹配率门槛 |
| `ADAPTIVE_NO_PROGRESS_ROUNDS` | `2` | 连续无进展轮数即停 |
| `ADAPTIVE_VALIDITY_SAMPLE` | `20` | 引用有效性抽样条数 |
| `ADAPTIVE_STATE_DIR` | `outputs/adaptive` | 状态与报告版本落盘目录 |

> 说明：**不修改** 既有 `MAX_ITERATIONS`（它的真实语义是"生成几条子查询"，见 `prompts.py:246`），避免语义混用（风险 R5）。

## 8. 测试方法（总体）

| 层 | 测试手段 | 是否需要真实 LLM |
| --- | --- | --- |
| state | 序列化往返、不变量校验 | 否 |
| budget | 注入假时钟/假用量，验证边界与熔断 | 否 |
| planner | 注入固定 JSON 响应，验证拆解与去重 | 否（stub） |
| metrics | 固定报告+证据 fixture，验证分母/分子 | 否（确定性指标） |
| reflection | 构造评估结果矩阵，验证决策表全覆盖 | 否 |
| orchestrator | 注入 FakeExecutor + FakeEvaluator，跑完整 2 轮 | 否 |
| 端到端 | 真实 DeepSeek + Tavily，1 个查询，对比原版 | 是（手动/夜间） |

**回归红线**：`pytest tests/` 全绿；`ADAPTIVE_ENABLED=false` 时，原有 CLI/Web 路径的输出与原版一致（可用同查询对比报告结构）。
