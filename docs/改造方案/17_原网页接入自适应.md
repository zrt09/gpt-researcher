# 17 原网页接入自适应模式（B 方案）

> 目标：**沿用项目原来的网页**（`frontend/index.html`），在报告类型里增加一个 “Adaptive” 选项；
> 研究过程中的**日志与质量指标**实时可见，报告在结束时一次性呈现，下载按钮保持原样。

---

## 1. 用户看到的完整流程

```powershell
# 必须用 main.py 启动（它会加载 .env 里的 API Key）
env\Scripts\python.exe main.py
```

浏览器打开 **http://127.0.0.1:8000/**，然后：

1. 输入问题，例如「2026年诺贝尔物理学奖得主及其主要贡献」；
2. 报告类型下拉框选择 **“Adaptive - 自适应研究（多轮评估，进度见日志）”**；
3. 点开始，右侧日志区依次出现：

```
🚀 自适应模式：最多 3 轮、120 次模型调用，评估模式 light
🔄 第 1 轮研究开始
🔎 子任务 1：2026年诺贝尔物理学奖获奖者
🌐 Browsing the web to learn more about the task: ...
...
✅ 第 1 轮完成：新增证据 32 条；覆盖度 0.80 / 引用可回溯 1.00 / 完整性 1.00 / 来源有效性 1.00；决策：结束
🏁 研究结束：已完成（质量达标）（stop_reason=quality_met，1 轮，成本估算 $0.0424）
```

4. 随后报告正文一次性出现；
5. 底部下载按钮照旧：**md / docx / json**（PDF 在 Windows 缺 GTK 时为空）。

> 报告为什么不是"逐字出现"：自适应版是"先大纲 → 分节并行写 → 装配"，没有连续字符流可转发。按你的选择，过程中看日志与指标即可，正文在结束时给出成品。

| 文件 | 改动 |

## 3. 消息映射（自适应事件 → 原 UI）

| 内部事件 | 发给页面的消息 | 页面表现 |
| --- | --- | --- |
| 启动 | `logs / starting_research` | 日志：最多几轮、评估模式 |
| `adaptive_round_started` | `logs / starting_research` | 日志：第 N 轮开始 |
| `query_planned` | `logs / subqueries` | 日志：子任务列表 |
| 每轮结束 | `logs / research_step_finalized` | 日志：新增证据数 + 四项指标 + 决策 |
| 运行结束 | `logs / research_step_finalized` | 日志：状态、停止原因、轮次、成本 |
| 最终报告 | `report`（整篇，一次） | 正文区域 |
| 文件生成 | `path`（由 `handle_start_command` 发出） | 下载按钮 |

子任务内部的搜索/抓取日志会**原样透传**（因为复用了 `GPTResearcher`），所以过程中信息密度很高。

## 5. 两个必须注意的点

### 5.1 必须用 `main.py` 启动

直接用 `uvicorn backend.server.app:app` 启动**不会加载 `.env`**，模型 Key 缺失，日志会出现：

```
adaptive planner LLM call failed: Missing credentials...
```

这是本次联调时踩到的坑，已确认 `main.py`（内部 `load_dotenv()`）正常。

### 5.2 轮次与评估模式暂时不能在网页上调

B 方案没有改前端表单，所以：

- `ADAPTIVE_MAX_ROUNDS`（默认 3）、`ADAPTIVE_EVAL_MODE`（默认 light）仍在 `.env` / 配置文件里改；
- 如果你希望网页上能选，后续加一个 `<select>` 传进 `start` 消息即可（约 30 行）。
