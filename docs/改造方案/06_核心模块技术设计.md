## 2. `state.py` —— 数据模型

详见 07 号文档。此处只给对外契约：

```python
@dataclass
class ResearchState:
    query: str
    plan: list[SubTask]
    evidence: list[Evidence]
    claims: list[Claim]
    rounds: list[RoundRecord]
    budget: BudgetState
    visited_urls: set[str]
    report: str | None
    status: RunStatus
    stop_reason: StopReason | None
    def open_tasks(self) -> list[SubTask]: ...
    def evidence_by_ids(self, ids: list[str]) -> list[Evidence]: ...
    def to_dict(self) -> dict: ...
    @classmethod
    def from_dict(cls, d: dict) -> "ResearchState": ...
```

不变量（`__post_init__` 校验）：

- `len(plan) <= ADAPTIVE_MAX_TASKS`；
- 每个 `SubTask.origin ∈ {initial, gap, replan}`；
- `status == COMPLETED` 时 `stop_reason` 必须非空且为 `QUALITY_MET`；
- `Evidence.task_id` 必须存在于 plan（允许指向已 closed 的任务）。

## 3. `budget.py` —— 预算与计数

### 职责
维护四类资源的累计值与上限，提供"可否继续"的廉价判断与"用尽原因"。

### 接口

```python
class StopReason(str, Enum):
    QUALITY_MET = "quality_met"
    MAX_ROUNDS = "max_rounds"
    MAX_LLM_CALLS = "max_llm_calls"
    MAX_TOKENS = "max_tokens"
    MAX_SECONDS = "max_seconds"
    MAX_COST = "max_cost"
    NO_PROGRESS = "no_progress"
    PLANNER_EXHAUSTED = "planner_exhausted"
    ERROR = "error"

@dataclass
class Usage:                       # 由 create_chat_completion 上报
    provider: str
    model: str
    input_tokens: int
    output_tokens: int
    cost_usd: float
    step: str = "adaptive"

class BudgetController:
    def __init__(self, limits: BudgetLimits, clock=time.monotonic): ...
    def record(self, usage: Usage) -> None: ...
    def can_start_round(self) -> tuple[bool, StopReason | None]: ...
    def can_call_llm(self, est_tokens: int = 1500) -> tuple[bool, StopReason | None]: ...
    def exhaust_reason(self) -> StopReason | None: ...
    def remaining(self) -> dict: ...      # 供报告附录
```

### 关键规则

1. **优先单调**：任一硬上限触顶后，`exhaust_reason()` 立即返回且不再被覆盖（保留"首次触顶原因"）。
2. **预估 + 实测**：`can_call_llm(est_tokens)` 用保守估计（默认 1500）做前置；`record()` 用真实用量修正。
3. **软上限**：`MAX_COST` 与 `MAX_TOKENS` 任一触顶即停；`MAX_SECONDS` 在每轮开始检查（不中断进行中的 LLM 调用，避免线程/异步取消复杂度）。
4. **不重复记账**：`record()` 只由 `usage_sink` 调用一次；`GPTResearcher.add_costs` 的美元统计保持不变（两套账互不覆盖，报告附录里并列展示）。

### 失败处理
- `clock` 可注入，便于单测模拟超时；
- `record()` 遇到负数/异常值抛出 `ValueError`（fail-fast，避免静默错账）。

### 单测点
- 恰好等于上限、超过 1 token、上限为 0；
- 首次触顶原因不被后续覆盖；
- 时钟推进模拟 `MAX_SECONDS`。

## 4. `planner.py` —— 规划与修订

### 职责
把研究问题拆成带目标的子任务；根据评估缺口增删改；做任务级去重。

### 接口

```python
class Planner:
    def __init__(self, cfg, prompt_family, budget: BudgetController | None = None): ...

    async def initial_plan(self, query: str) -> list[SubTask]:
        """首轮拆解，3~6 个任务，每个含 query + goal。"""

    async def revise(self, state: ResearchState, evaluation: EvaluationResult) -> list[SubTask]:
        """根据 deficits 生成**新**任务（不改已有任务），返回去重后的增量。"""

    def _dedupe(self, candidates: list[SubTask], existing: list[SubTask]) -> list[SubTask]:
        """query 归一化 + 词面/语义相似度去重，阈值可配。"""
```

### 关键算法

**首轮拆解**
- 一次 `create_chat_completion(strategic_llm)`，要求 JSON：`[{"query": "...", "goal": "..."}]`；
- 解析走 `json_repair`（与 `_normalize_sub_queries` 一致的容错风格），失败则退化为"原问题 + 2 个固定视角"（避免一个坏响应让整个流程失败）；
- 强制补一个"总览任务"（query=原问题），保证基准覆盖。

**修订**
- 输入：`evaluation.deficits`（每条形如 `kind=missing_coverage, task_id=T3, description=..., suggested_query=...`）；
- 对 `missing_coverage` 直接复用 `suggested_query`；对 `weak_evidence` 生成"限定来源类型/时间"的检索式；对 `conflict` 生成"交叉验证"检索式；
- 新增任务数受 `ADAPTIVE_MAX_TASKS - len(plan)` 约束。

**去重（关键，防重复研究）**
1. 归一化：小写、去停用词、去标点、数字保留；
2. 词面：`rapidfuzz`（已是依赖）`token_set_ratio >= 85` 判为重复；
3. 语义（可选）：若 embedding 可用，余弦 `>= 0.9` 判重；
4. 与 `existing` 及**已 closed 任务**比较，避免重复研究已完成内容；
5. 命中重复时，把候选的 `goal` 合并进已有任务的 `goal`（信息不丢）。

### 失败处理
- LLM 失败 → 重试 1 次（复用 `create_chat_completion` 内部重试）→ 仍失败则返回空增量并记录 `planner_failed` 事件，由 Reflection 决定 `finish(partial)` 还是 `error`。
- 解析出 0 个任务 → 同上，**不得**伪造计划。

### 单测点
- 固定 JSON 响应 → 任务数/字段正确；
- 畸形 JSON → 走降级计划；
- 相似 query（"RAG 的局限"/"RAG 有哪些局限"）→ 判重；
- 超出 `MAX_TASKS` → 截断且不报错。

## 5. `executor.py` —— 子任务执行适配

### 职责
把一个 `SubTask` 变成证据；复用原版研究链路，不重写检索/抓取/压缩。

### 接口

```python
@dataclass
class TaskResult:
    task_id: str
    status: TaskStatus              # DONE / FAILED
    evidence: list[Evidence]
    context: str                    # 该任务压缩后的上下文（供写作/评估）
    sources: list[dict]
    tokens: int
    cost_usd: float
    error: str | None

class ResearchExecutor:
    def __init__(self, cfg, shared_visited_urls: set[str], usage_sink=None,
                 artifact_sink=None, websocket=None): ...

    async def run_task(self, task: SubTask, *, role=None, agent=None) -> TaskResult:
        """一个子任务 = 一个 GPTResearcher 实例（共享 visited_urls）。"""
```

### 实现要点

```python
researcher = GPTResearcher(
    query=task.query,
    report_type=ReportType.ResearchReport.value,   # 只研究，不写报告
    report_source=ReportSource.Web.value,
    visited_urls=self.shared_visited_urls,          # 跨任务去重
    agent=agent, role=role,                         # 跳过 choose_agent，省一次 LLM
    config_path=self.config_path,
    websocket=self.websocket,
    artifact_sink=self._capture,                    # 新增可选参数（B 类改动）
    usage_sink=self.usage_sink,
)
context = await researcher.conduct_research()
```

`_capture(sub_query, pages, compressed)`：

- 对 `pages` 每条取 `url/title/raw_content`；
- 用 `context/select.py select_context()` 依据 `sub_query` 选出 top-k 片段（或直接切 `compressed` 的段落）；
- 生成 `Evidence(id="E{task}-{i}", task_id, url, title, snippet, fetched_at, query, round)`；
- 单任务 Evidence 上限可配（默认 8 条，避免状态爆炸）。

### 失败处理
- `conduct_research()` 抛异常或返回空 → `TaskResult(status=FAILED, error=...)`，**不得**返回"看起来成功"的空证据；
- 重试策略：任务级最多 2 次（与 LLM 的内部重试分开计数）；
- 超时：单任务 `asyncio.wait_for`，上限可配（默认 180s）。

### 单测点
- 注入 Fake `GPTResearcher`（monkeypatch）→ 证据条数/字段正确；
- 抛异常 → FAILED 且 error 非空；
- `visited_urls` 在两次 run 之间确实共享。

## 6. `metrics.py` + `evaluator.py` —— 质量评估

### 6.1 指标实现（`metrics.py`，纯函数为主）

| 函数 | 输入 | 输出 | 成本 |
| --- | --- | --- | --- |
| `coverage(state)` | state | `{value, covered, total, per_task}` | 0 |
| `citation_presence(report, evidence)` | 报告文本 + 证据 | `{value, citations, resolvable}` | 0 |
| `citation_semantic_match(claims, evidence, judge)` | 结论 + 证据 + 判定函数 | `{value, matched, total}` | LLM（可选） |
| `support_rate(claims, judge)` | 结论列表 | `{value, supported, total}` | LLM |
| `source_validity(urls, sampler)` | URL 列表 | `{value, ok, checked, failures}` | HTTP |
| `source_freshness(evidence)` | 证据 | `{value, fresh, dated}` | 0 |
| `conflict_rate(claims, judge)` | 结论列表（抽样） | `{value, pairs, conflicts}` | LLM |
| `completeness(report, plan)` | 报告 + 计划 | `{value, sections_present, required}` | 0 |

复用：`citation_presence` 的 URL 抽取、`source_diversity` 等领域打分，**直接 import** `evals/quality_eval/metrics.py` 中的实现，不重写。

### 6.2 评估调度（`evaluator.py`）

```python
class ResearchEvaluator:
    def __init__(self, cfg, judge=None): ...   # judge: async (prompt) -> str，可注入假实现
    async def evaluate(self, state, report: str, mode: str = "light") -> EvaluationResult:
        """light: 0 成本指标 + 抽样 URL 有效性；full: 外加 LLM 判定。"""
```

**light 模式的步骤**
1. `claims = extract_claims(report)`：**结构化解析**（按 `##` 分节 + 抽取含引用标记的句子），不调 LLM；
2. `coverage`、`citation_presence`、`source_freshness`、`completeness` 纯计算；
3. `source_validity`：按 `ADAPTIVE_VALIDITY_SAMPLE` 抽样做 HTTP 检查（`httpx`，超时 5s，并发 8，`HEAD` 失败再 `GET` 首字节）；
4. 汇总为 `EvaluationResult(passed=QualityGate.check(...))`。

**full 模式的额外步骤**
5. `support_rate`：把 claims 按 10 条/批，逐批判定 `supported/weak/unsupported`，要求判定附证据 id；
6. `citation_semantic_match`：只对"有引用但无同源证据"的 claim 做语义判定；
7. `conflict_rate`：仅当 claim 数 > 10 时抽样 10 条，两两比对可能导致矛盾的数值/结论。

**成本护栏**：full 模式的 LLM 调用数上限 = `ceil(claims/10) * 2`，超过则截断并标记 `sampled=True`。

### 失败处理
- 任一指标抛异常 → 该指标记为 `MetricResult(value=None, error=...)`，**不**让评估整体失败；
- `EvaluationResult.passed` 在"关键指标缺失"时取 `False`（宁可多补一轮，不可误判达标）。

### 单测点
- 固定报告 + 证据 fixture，验证每个指标的分子/分母（含空集边界：分母 0 时 `value=None`，而不是 1.0）；
- `judge` 注入固定响应，验证批处理与截断；
- HTTP 抽样注入假 sampler，验证超时与失败统计。

## 7. `reflection.py` —— 反思与决策

### 职责
把"评估结果 + 状态 + 预算"映射为一个**可执行动作**。原则：**能用规则就不用 LLM**。

### 接口

```python
class Action(str, Enum):
    SUPPLEMENT = "supplement"    # 补充研究
    REPLAN = "replan"            # 整体重规划
    REWRITE = "rewrite"          # 只重写报告
    FINISH = "finish"
    ABORT = "abort"              # 不可恢复

@dataclass
class Decision:
    action: Action
    reason: str
    new_tasks: list[SubTask]
    rewrite_notes: list[str]

class ReflectionEngine:
    def decide(self, ev: EvaluationResult, state: ResearchState, budget: BudgetController) -> Decision: ...
```

### 决策规则（优先级从高到低）

| 条件 | 动作 |
| --- | --- |
| `budget.exhaust_reason()` 非空 | `FINISH`（`stop_reason` 已定） |
| `ev.passed` 且无 `unsupported` claim | `FINISH(QUALITY_MET)` |
| 存在 `missing_coverage` 缺口 | `SUPPLEMENT`（生成补研任务） |
| `support_rate < 门槛` 且 `citation_presence` 高 | `SUPPLEMENT`（找更强证据） |
| `support_rate < 门槛` 且证据已足够（证据覆盖了所有 claim 来源） | `REWRITE`（收紧表述、删去无据结论） |
| 缺口涉及 ≥ 2 个任务且计划明显错位 | `REPLAN` |
| 连续 `ADAPTIVE_NO_PROGRESS_ROUNDS` 轮指标无提升 | `FINISH(NO_PROGRESS)` |
| 评估全部失败（无任何有效指标） | `ABORT` |

**LLM 的角色**：只在 `SUPPLEMENT` 时用一次 LLM 把 `deficits` 转成具体检索式（复用 Planner 的 prompt）；其余全部规则化。

### 失败处理
- 决策函数是纯函数（除 LLM 辅助生成检索式），**必须**对任意输入返回决策，不抛异常；
- 未覆盖的条件组合 → 兜底 `FINISH(NO_PROGRESS)`（安全侧）。

### 单测点
- 决策表逐行覆盖（构造最小 `EvaluationResult`）；
- 预算耗尽优先级最高；
- 所有指标缺失 → `ABORT`。

## 8. `orchestrator.py` —— 主循环

### 接口

```python
@dataclass
class AdaptiveResult:
    report: str
    evaluation: EvaluationResult | None
    state: ResearchState
    status: RunStatus
    stop_reason: StopReason

class AdaptiveResearcher:
    def __init__(self, query: str, *, cfg: Config | None = None, config_path: str | None = None,
                 websocket=None, observer=None, budget_overrides: dict | None = None): ...
    async def run(self, on_round: Callable[[RoundRecord], None] | None = None) -> AdaptiveResult: ...
```

### 循环实现要点

- 每轮开始：`budget.can_start_round()`，失败则 `break`；
- 任务并发：`asyncio.Semaphore(ADAPTIVE_CONCURRENCY)`（默认 3），避免把 Tavily 打挂；
- 每轮结束：写入 `RoundRecord`，`emit_research_event("adaptive_round_completed", ...)`，`state` 落盘（`state.json`）；
- 报告版本：`outputs/adaptive/<run_id>/report_v{n}.md`，保留全部版本（过程记录要求）；
- 最终状态：`COMPLETED / PARTIAL / FAILED`，**不允许**在未达标时写 `COMPLETED`。

### 异常策略
- 单任务失败：记录并继续（不中断整轮）；
- 规划/评估彻底失败：`ABORT` → `status=FAILED`，报告仍输出"已完成部分 + 失败原因"（不伪造）；
- 进程级异常：`try/finally` 保证 `state.json` 已落盘。

### 单测点
- 注入 FakeExecutor/FakeEvaluator/FakePlanner → 2 轮后 `QUALITY_MET`；
- 预算 1 轮即耗尽 → `MAX_ROUNDS` 且报告含缺口附录；
- 任务全部失败 → `FAILED` 且 `open_questions` 非空。

## 9. 对原包的 6 处最小改动（逐处说明）

### 9.1 `gpt_researcher/utils/llm.py`（B）

```python
async def create_chat_completion(..., usage_sink: Callable[..., None] | None = None):
    ...
    if cost_callback or usage_sink:
        llm_costs = calculate_llm_cost(...)
    if cost_callback:
        cost_callback(llm_costs)
    if usage_sink:
        # 以关键字参数上报，核心包因此不需要 import gpt_researcher.adaptive
        usage_sink(provider=..., model=..., input_tokens=..., output_tokens=...,
                   cost_usd=llm_costs, estimated=...)
```
- **实现偏差（已落地）**：原设计让 `usage_sink` 接收 `Usage` 对象，但那会让核心包反向依赖 `adaptive`。实现改为**关键字参数协议**，由 `adaptive` 侧包装成 `Usage`。
- token 来源：优先 `provider.last_usage_metadata`（LangChain `usage_metadata`），缺失时用 `tiktoken` 估算并置 `estimated=True`。
- sink 内部异常只记 warning，**绝不**影响 LLM 调用。
- **无 usage_sink 时行为完全不变**。

### 9.2 `gpt_researcher/agent.py`（B，实现时已收缩）

## 10. 端到端时序（一次 run，2 轮）

```
用户 → AdaptiveResearcher.run
  ① Planner.initial_plan → 4 个任务
  ② Round1:
       executor.run_task ×4（并发 3）→ Evidence ×N
       writer.write(evidence) → draft v1
       evaluator.evaluate(light) → coverage 0.5, citation 0.9 → passed=False

       writer.write(evidence, revision_notes) → draft v2

  ④ Budget: 未触顶 → FINISH(QUALITY_MET)
```

## 11. 与"不伪造完成"的契约

| 情况 | `status` | 报告必须包含 |
| --- | --- | --- |
| 全部指标达标 | `COMPLETED` | 评估摘要（通过项） |
| 预算耗尽但部分完成 | `PARTIAL` | **未解决问题清单 + 缺口表 + 触顶原因** |
| 研究/评估全面失败 | `FAILED` | 失败原因 + 已完成部分 + 建议的人工下一步 |
| 评估数据缺失 | `PARTIAL` | "本次未能完成质量校验"的明确声明 |

> 这三行是"验收标准 9"与"不得伪造完成"的落地检查点，需在阶段 6 集成测试中用 fixture 强制验证。
