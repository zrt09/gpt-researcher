## 7. 已知问题清单

### 问题 1（会直接影响运行）：`RETRIEVER=competitor_monitor` 是无效检索器

- `.env` 中 `RETRIEVER=competitor_monitor`；
- 但 `gpt_researcher/retrievers/competitor_monitor/` 下**只剩 `__pycache__/*.pyc`，没有任何 `.py` 源码**；
- `get_all_retriever_names()`（`gpt_researcher/retrievers/utils.py`）只按"目录是否存在"判定合法名，所以这个空目录**仍然被登记为合法检索器**；
- 于是 `Config.parse_retrievers()` 不会报错，运行时 `actions/retriever.py get_retriever()` 才会因找不到模块而失败（或触发回退）。

这是上一轮"competitor-monitor"试验被删除源码后留下的残留（同样残留的还有 `gpt_researcher/competitive_intel/`，也只剩 `.pyc`）。两者都**未被 Git 跟踪**，属于本地脏数据。

**建议处理（需你确认）**：把 `.env` 的 `RETRIEVER` 改回 `tavily`；删除两个只含 `__pycache__` 的残留目录。**本阶段未做任何改动。**

### 问题 2：测试依赖未安装

见第 5 节。影响：任何"回归测试"承诺目前都无法兑现。

### 问题 3：没有版本基线标签

`git tag` 为空，且 `main` 领先 `origin/main` 136 个提交。意味着"原版"目前只是一个移动的分支指针，不可追溯。

**建议**：在 `main` 上打 `baseline-original-v0.17.0` 标签后再进入开发（阶段 3 落实）。

### 问题 4：仓库根目录有若干临时目录

`tmpn3t7yqyc`、`tmpndj3vcx4`、`tmpxmr6rplm`、`tmp_tx6xmf2`、`__pycache__` 等，均未跟踪。属运行残留，不影响功能，可后续清理。
