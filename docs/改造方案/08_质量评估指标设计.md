# 08 质量评估指标设计

> 原则（任务书 2.4）：每项指标必须说明**定义、计算方式、数据来源、评估方法、是否需人工标注、可能误差**；
> **禁止**使用一个没有计算依据的综合分数。

---

## 0. 设计结论先行

1. 采用**"分项指标 + 门槛（gate）"**，不设"综合质量分"。报告里只展示分项值与是否达标，避免把不可比的东西加权成一个数字。
2. 指标分三档成本：**零成本（纯计算）→ 近零成本（HTTP 抽样）→ 有成本（LLM 判定）**，默认 `light` 模式只跑前两档。
3. 所有指标输出统一结构 `MetricResult{value, numerator, denominator, method, sampled, notes}`，**分母为 0 时 `value=None`**（表示"无法计算"），绝不用 1.0 冒充满分。
4. 7 项指标中，**4 项零成本**（M1 覆盖度、M3 引用可解析、M5 时效性、M7 完整性），这是"每轮都能评估"的前提。

## 1. 指标总表

| 编号 | 指标 | 成本档 | 默认启用 | 门槛（默认） |
| --- | --- | --- | --- | --- |
| M1 | 研究问题覆盖度 coverage | 零 | ✅ light | ≥ 0.80 |
| M2 | 关键结论证据支持率 support_rate | LLM | ✅ full | ≥ 0.85 |
| M3 | 引用—结论匹配率 citation_match | 零 + LLM | ✅ light(零) + full(语义) | ≥ 0.80 |
| M4 | 来源有效性 source_validity | HTTP 抽样 | ✅ light | ≥ 0.90 |
| M5 | 来源时效性 source_freshness | 零 | ✅ light | 仅报告，不设门槛 |
| M6 | 信息冲突识别 conflict_rate | LLM 抽样 | ✅ full | ≤ 0.10（越低越好） |
| M7 | 研究结果完整性 completeness | 零 | ✅ light | ≥ 0.90 |

## 2. M1 研究问题覆盖度（coverage）

| 项 | 内容 |
| --- | --- |
| **定义** | 已完成的子任务中，能在报告里找到对应内容的比例；用于回答"计划里的问题是否都被回答了" |
| **计算** | `coverage = |{ t ∈ plan : covered(t) }| / |{ t ∈ plan : t.status ≠ SKIPPED }|`<br>`covered(t) = (t.status == DONE) ∧ ∃claim ∈ claims: t.id ∈ claim.task_ids` |
| **数据来源** | `State.plan`（任务与状态）+ `State.claims.task_ids`（light 模式由章节标题与任务 goal 的**词面匹配**回填；full 模式由 LLM 抽取时直接标注） |
| **评估方法** | 确定性计算；`covered` 的任务归属在 light 模式下用 `rapidfuzz.token_set_ratio(goal, section_title) ≥ 70` 近似 |
| **人工标注** | 否（抽样复核建议） |
| **误差** | ① 章节标题与 goal 措辞差异 → 漏判（偏低）；② 一个章节覆盖多个任务 → 归属不确定。**故 light 模式的覆盖度是保守下界** |
| **失败处理** | `plan` 为空 → `value=None` |

## 3. M2 关键结论证据支持率（support_rate）

| 项 | 内容 |
| --- | --- |
| **定义** | 报告中抽出的结论句中，能在本轮证据里找到支撑的比例 |
| **计算** | `support_rate = |{c : c.support == SUPPORTED}| / |{c : c.support ≠ UNCHECKED}|`<br>WEAK 计 0.5（在 `notes` 中单列，不混入分子） |
| **数据来源** | `State.claims` + `State.evidence` |
| **评估方法** | **LLM 判定**：每条 claim 附带 ≤3 条候选证据片段（按 URL 命中优先、语义相似次之），要求模型输出 `{supported|weak|unsupported, evidence_id, reason}`，且 `evidence_id` 必须在给定集合内（否则判 `unchecked` 并计入失败） |
| **人工标注** | 校准阶段建议标注 30~50 条以估计判定准确率；运行时不需人工 |
| **误差** | ① 同一模型自评（本机三档均为 deepseek-chat）→ 偏乐观；② 证据片段被压缩截断 → 判 unsupported 的假阳性；③ 模型可能编造 `evidence_id`（用集合校验拦截） |
| **成本** | 每 10 条 claim 一次调用；上限 `ceil(claims/10)`，超出截断并 `sampled=True` |

## 4. M3 引用—结论匹配率（citation_match）

分两部分，可以分开看：

### M3a 引用可解析率（零成本）

| 项 | 内容 |
| --- | --- |
| **定义** | 报告中出现的引用链接，能在本轮证据集中找到同源的比例 |
| **计算** | `citation_match_url = |{url ∈ cited_urls : url ∈ evidence_urls}| / |cited_urls|`（URL 归一化：去 `#fragment`、去尾斜杠、小写 host） |
| **数据来源** | 报告正则抽取 `https?://...` + `State.evidence.url` |
| **评估方法** | 确定性集合运算 |
| **人工标注** | 否 |
| **误差** | 报告里的链接可能是"参考过的页面"而非"支撑该句的页面"——所以这只能证明"引用不是凭空的"，**不能**证明"引用支撑结论"（那由 M3b 补） |

### M3b 引用支撑结论率（LLM，full 模式）

| 项 | 内容 |
| --- | --- |
| **定义** | 有引用的结论中，引用来源的内容确实支持该结论的比例 |
| **计算** | `citation_match_semantic = supported / judged`，只对"M3a 命中但对不上同源证据"的 claim 做判定，减少调用 |
| **数据来源** | claim 原文 + 其 `cited_urls` 对应的 evidence 片段 |
| **评估方法** | LLM 二分类 + 理由（要求引用原文片段） |
| **人工标注** | 建议 30 条校准 |
| **误差** | 证据片段不完整 → 误判"不支持"；模型对"部分支持"边界不稳定（故设 `weak` 档） |

## 5. M4 来源有效性（source_validity）

| 项 | 内容 |
| --- | --- |
| **定义** | 被引用的 URL 中，仍然可访问（HTTP 2xx/3xx）的比例 |
| **计算** | `validity = ok / checked`；抽样 `ADAPTIVE_VALIDITY_SAMPLE`（默认 20）条，随机但确定性种子（`run_id`）保证可复现 |
| **数据来源** | `State.evidence.url`（去重后） |
| **评估方法** | HTTP 检查：`HEAD` 超时 5s → 失败回落 `GET`（只读首字节）；并发 8；**不抓正文**（省流量与时间） |
| **人工标注** | 否 |
| **误差** | ① 站点反爬返回 403/429 → 误判失效（应把 401/403/429 归为 `blocked` 而非 `invalid`）；② 重定向到登录页仍算 2xx → 漏判；③ 无网络时全部失败 → 指标 `value=None` + `notes="network_unavailable"` |
| **成本** | 最多 20 次请求，约 5~10 秒 |

---

## 6. M5 来源时效性（source_freshness）

| 项 | 内容 |
| --- | --- |
| **定义** | 有发布时间的来源中，发布在"可接受窗口"内的比例 |
| **计算** | `freshness = fresh / dated`；窗口默认 **24 个月**（可配 `ADAPTIVE_FRESHNESS_MONTHS`） |
| **数据来源** | `Evidence.published_at`（从页面 meta/JSON-LD 抽取，抓取器已有 `extract_title` 类似的工具位） |
| **评估方法** | 纯计算；**只对"有日期"的来源计算**，并在 `notes` 里报告 `dated/total` 的覆盖率 |
| **人工标注** | 否 |
| **误差** | 发布时间缺失率可能很高（新闻/博客常有，文档站常无）→ 覆盖率低时该指标参考价值有限，**因此不设门槛**，只展示 |
| **失败处理** | `dated == 0` → `value=None` |

---

## 7. M6 信息冲突识别（conflict_rate）

| 项 | 内容 |
| --- | --- |
| **定义** | 被比较的结论对中，彼此矛盾（同一事实给出不同数值/相反结论）的比例 |
| **计算** | `conflict_rate = conflicts / pairs_compared`；抽样：claim 数 > 10 时随机 10 条两两比较（≤45 对，再抽 10 对） |
| **数据来源** | `State.claims`（需包含数值/断言） |
| **评估方法** | LLM 判定"是否矛盾"，要求给出两边的原文；只判"同一对象、同一时间维度"的冲突 |
| **人工标注** | 建议人工复核发现的冲突（数量少，价值高） |
| **误差** | ① 不同时间点的数据被误判为冲突（要求带时间维度）；② 抽样导致漏检；③ 模型倾向于"发现冲突" |
| **门槛** | ≤ 0.10；高于门槛 → `Deficit(kind=conflict)`，触发交叉验证补研 |

---

## 8. M7 研究结果完整性（completeness）

| 项 | 内容 |
| --- | --- |
| **定义** | 报告应包含的结构（引言、主体章节、结论、参考文献）齐全、且每个主体章节非空并有引用 |
| **计算** | `completeness = 满足条件的必需项数 / 必需项数`；必需项 = {intro, ≥2 主体章节, conclusion, references}，主体章节"合格"= 正文 ≥120 字且含 ≥1 引用 |
| **数据来源** | 报告 markdown（复用 `actions/markdown_processing.py:extract_sections`） |
| **评估方法** | 确定性解析 |
| **人工标注** | 否 |
| **误差** | 非常规结构（如纯表格报告）可能误判；对中文标题的 `##` 解析依赖固定格式（原项目报告就是 markdown 标题结构，风险低） |

## 9. 门槛（QualityGate）与"达标"定义

```
passed =  coverage      >= MIN_COVERAGE (0.80)
       AND citation_url >= MIN_CITATION_MATCH (0.80)      # M3a，零成本版本
       AND completeness >= MIN_COMPLETENESS (0.90)
       AND (mode == "light" OR support_rate >= MIN_SUPPORT_RATE (0.85))
       AND (mode == "light" OR conflict_rate <= MAX_CONFLICT (0.10))
```

规则：

1. **不计算加权总分**。理由：覆盖度与引用匹配不是同一量纲，加权系数没有依据（任务书明确禁止无依据的综合分）。
2. 任一指标 `value=None` 且属于"必需指标"（coverage/citation_url/completeness）→ `passed=False`，并在 `notes` 标明"未能校验"，由决策层选择再评估一轮或降级为 `PARTIAL`。
3. 门槛值集中在配置里，**必须**先用基线数据校准（见第 11 节），不得拍脑袋定稿。

## 10. 抽样与成本预算（估算）

| 指标 | 单轮调用数（light） | 单轮调用数（full） |
| --- | --- | --- |
| M1/M5/M7 | 0 | 0 |
| M3a | 0 | 0 |
| M4 | 0（HTTP） | 0（HTTP） |
| M2 | — | ⌈claims/10⌉（≤3） |
| M3b | — | ≤2 |
| M6 | — | ≤2 |
| **合计 LLM 调用** | **0** | **≤7** |

以基线实测单次研究 ≈ **$0.0111 / 约 2.2 万报告字符**为参照：一轮 full 评估（≈7 次调用，输入以证据片段为主）预计 **$0.003~0.008**；3 轮 full ≈ $0.01~0.025，约为基线成本的 1~2 倍。**这是可接受的**；若改用每轮 full，总成本仍在 $0.05 以内。

> 注意：以上为估算，需在阶段 6 用真实调用校准并记录到对照实验报告。

## 11. 阈值校准方法（阶段 6 执行）

1. 用 5~10 个固定查询跑**原版**研究，记录每个查询的 M1/M3a/M7 分项值；
2. 人工标注其中 2~3 个查询的"实际覆盖情况/引用是否支撑"，作为参照；
3. 取原版分位数的中位数附近作为初始门槛（例如原版 coverage 中位数 0.6 → 门槛设 0.8 才有改进空间，但也不至于不可达）；
4. 校准结果与理由写入 `13_项目风险清单.md` / 对照实验报告，**不得静默改门槛**。

## 12. 指标到缺陷（Deficit）的映射

| 指标不达标 | 生成的缺陷 | 触发的行动 |
| --- | --- | --- |
| M1 低 | `missing_coverage(task_id)` | 补研缺失子任务 |
| M2 低 | `weak_evidence(claim_id)` | 找更强证据（补研）或收紧表述（重写） |
| M3a 低 | `broken_citation(url)` | 补研该引用来源 / 删除无源引用 |
| M3b 低 | `weak_evidence(claim_id)` | 同 M2 |
| M4 低 | `broken_citation(url)` | 替换来源 |
| M6 高 | `conflict(claim_pair)` | 交叉验证补研 |
| M7 低 | `incomplete(section)` | 重写该章节 |

> 映射是 `reflection.py` 决策表的输入，保证"评估→行动"可解释、可测试。
